# Sprint 1 스토리 — 걸어다니는 뼈대

> 목표: 한 번 굴리면 돌아왔을 때 브랜치에 결과물과 보고서가 있다. 얇게, 딱 한 번.
> 상태: 확정 v1.0

---

### S1-01 — conductor 스킬 골격
- **사용자 스토리**: 사용자로서 "conductor로 X 해줘" 한마디로 자율 실행을 시작하고 싶다, 매번 절차를 설명하지 않기 위해.
- **인수 조건**
  - Given 스킬이 설치된 상태 / When 사용자가 자율 실행을 요청 / Then 킥오프 → 실행계획 기록 → 병렬실행 → 통합 → 커밋·푸시 → 보고 순서로 진행한다
  - Given 실행이 시작된 뒤 / When 애매한 판단이 필요 / Then 사용자에게 묻지 않고 원칙에 따라 결정하고 그 결정을 기록한다
  - Given 킥오프 / When 질문 / Then 최대 3개까지만 묻는다: ①무엇을 완성해야 하나 ②완료를 어떻게 판단하나 ③건드리면 안 되는 것
  - Given 요청에 이미 그 답이 들어 있음 / When 킥오프 / Then 해당 질문을 생략하고 바로 계획으로 넘어간다
- **기술 메모**: `.claude/skills/conductor/SKILL.md`. 트리거 문구에 "자율", "알아서", "자리 비운다", "에이전트 여러 개" 포함.
- **크기**: M · **의존**: 없음

### S1-02 — 작업 분해와 병렬 레인 배치
- **사용자 스토리**: 사용자로서 일이 안전하게 병렬로 쪼개지길 바란다, 동시 실행이 오히려 서로를 망치지 않도록.
- **인수 조건**
  - Given 분해된 작업 목록 / When 레인을 배치 / Then 같은 파일에 쓰는 작업이 서로 다른 레인에 배정되지 않는다
  - Given 두 작업이 서로의 결과에 의존 / When 배치 / Then 병렬이 아니라 직렬로 표시된다
  - Given 작업이 아주 많음 / When 배치 / Then 동시 실행은 3~5개를 넘지 않는다
  - Given 조사·탐색성 작업 / When 배치 / Then 쓰기 충돌이 없으므로 팬아웃 우선 대상이 된다
- **크기**: M · **의존**: S1-01

### S1-03 — 콜드스타트 브리핑 템플릿
- **사용자 스토리**: 지휘자로서 각 에이전트에게 맥락을 충분히 떠먹여 보내고 싶다, 에이전트는 대화를 하나도 모른 채 시작하기 때문에.
- **인수 조건**
  - Given 에이전트에게 보낼 브리핑 / When 작성 완료 / Then 목표·범위·읽어야 할 파일·건드리면 안 되는 것·완료 기준·반환 형식이 모두 들어 있다
  - Given 브리핑 문안 / When 검토 / Then "아까 말한", "위에서 정한" 같은 대화 맥락 참조 표현이 없다
  - Given 브리핑만 읽은 제3자 / When 작업을 시작 / Then 추가 질문 없이 착수할 수 있다
- **크기**: S · **의존**: S1-01

### S1-04 — 결과 통합과 커밋·푸시
- **사용자 스토리**: 사용자로서 자리를 비운 사이의 결과가 사라지지 않길 바란다, 원격 컨테이너는 회수되기 때문에.
- **인수 조건**
  - Given 실행 시작 / When 브랜치 준비 / Then 주행마다 새 브랜치 `conductor/<과제slug>` 를 만든다 (실패한 주행이 성공한 주행을 오염시키지 않도록)
  - Given 모든 레인 완료 / When 통합 / Then 결과가 그 브랜치에 커밋되고 푸시된다
  - Given 일부 레인 실패 / When 통합 / Then 성공한 결과만 커밋하고 실패 사실을 보고서에 남긴다 (전체 폐기 금지)
  - Given 통합 중 충돌 / When 처리 / Then 임의 병합 대신 충돌 사실을 보고서에 명시한다
  - Given 실행 종료 / When 확인 / Then PR 생성·머지·배포는 하지 않는다
- **크기**: M · **의존**: S1-02

### S1-05 — 실행 기록: 계획 선기록 + 결과 보고서 v1
- **사용자 스토리**: 사용자로서 돌아왔을 때 무슨 일이 있었는지 한 장으로 파악하고 싶다, 다음 판을 바로 짜기 위해.
- **인수 조건**
  - Given 계획 수립 완료 / When 실행 시작 **전** / Then 실행 계획을 run 파일에 먼저 쓰고 커밋한다 (세션이 중간에 죽어도 의도가 남도록)
  - Given 실행 종료(성공이든 실패든) / When 보고서 생성 / Then `docs/runs/YYYY-MM-DD-<slug>.md` 에 4개 절이 남는다: 만든 것 / 내린 가정과 결정 / 막힌 것 / 다음 추천
  - Given 실행 중 내린 판단 / When 보고서 작성 / Then 각 판단과 그 근거가 결정 목록에 있다
  - Given 타임박스 초과로 중단 / When 보고서 생성 / Then 어디까지 했고 무엇이 남았는지가 적힌다 (빈손 금지)
- **크기**: S · **의존**: S1-01

### S1-06 — 리허설 무감독 주행
- **사용자 스토리**: 사용자로서 이 뼈대가 실제로 도는지 보고 싶다, 나머지 스프린트의 크기를 조절하기 위해.
- **인수 조건**
  - Given `개발시작하기` 스킬의 **트리거 테스트**(어떤 문장에서 스킬이 켜져야 하고 어떤 문장에서 안 켜져야 하는지 목록을 만들고 검사) 과제 / When conductor로 무감독 실행 / Then 사용자 질문 0회로 완주한다
  - Given 트리거 테스트 결과 / When 확인 / Then 켜져야 할 문장과 안 켜져야 할 문장이 각각 판정되어 남는다 (자동 검증이 가능한 형태라 Sprint 2 검증 게이트의 첫 적용 대상이 된다)
  - Given 실행 완료 / When 확인 / Then 브랜치에 결과물과 보고서가 커밋되어 있다
  - Given 30~60분 경과 / When 미완 / Then 거기까지의 결과와 남은 일이 보고된다
  - Given 주행 종료 / When 회고 / Then 뼈대에서 드러난 문제가 Sprint 2 입력으로 기록된다
- **크기**: L · **의존**: S1-01 ~ S1-05
