# 주행 기록: dev-kickoff 트리거 테스트

- **일시**: 2026-09-01
- **과제**: `개발시작하기`(dev-kickoff) 스킬의 트리거 테스트를 만들고 실행한다
- **맥락**: Sprint 1 / S1-06 리허설 주행. conductor 뼈대가 실제로 도는지 측정하는 것이 목적이다
- **상태**: 계획 기록됨 (실행 전)

## 킥오프

세 질문의 답이 이미 레포 문서에 있어 **아무것도 묻지 않았다.**

1. 무엇이 완성되어야 하나 → 트리거 테스트 세트 + 자동 실행 러너 + 판정 결과 (`docs/stories/sprint-1.md` S1-06)
2. 완료를 무엇으로 판단하나 → 켜져야 할 문장과 안 켜져야 할 문장이 각각 판정되어 파일로 남는다
3. 건드리면 안 되는 것 → `docs/prd.md`, `docs/sprints.md`, `docs/stories/` (합의된 기획 문서)

## 실행 계획

| 레인 | 작업 | 쓰기 대상 | 완료 기준 |
|---|---|---|---|
| A | should-trigger 쿼리 10개 작성 | `evals/dev-kickoff/triggers.json` | 표현이 서로 다른 10개, 스킬명 직접 언급 없는 것 포함 |
| B | should-not-trigger 쿼리 10개 작성 (근접 오답 위주) | `evals/dev-kickoff/triggers.json` | 키워드는 겹치나 실제로는 다른 것을 원하는 10개 |
| C | 자동 러너 작성 | `scripts/trigger_test.py` | 각 쿼리를 판정해 결과 파일과 통과율을 낸다 |
| D | 실행 및 판정 | `evals/dev-kickoff/results.*` | 20개 전부 판정, 오답 목록 확보 |

- A와 B는 같은 파일에 쓰므로 **한 레인으로 합친다** (레인 규칙: 같은 파일 = 같은 레인).
- C는 쓰기 대상이 겹치지 않아 병렬 가능.
- D는 A·B·C의 산출물이 모두 필요하므로 **직렬**.

## 검증 방법

작업 성격이 "스크립트·도구"이므로 실제로 한 번 돌려서 출력을 본다. 러너가 20개를 전부 판정하고 통과율을 내면 통과.

## 타임박스

30~60분. 초과 시 거기까지의 결과를 이 파일에 남기고 중단한다.
